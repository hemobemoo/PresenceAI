# 0029 — T1-r1: training, pick, export and scoring of the first verbatim Whisper (PR-4)

- Status: **proposed** (owner's answers Q1–Q4 of 2026-11-28 written in; waits for the owner's
  acceptance). Values marked PROVISIONAL may change only as a new named run (§1).
- Date: 2026-11-28
- Decider: project owner
- Plan reference: FINAL_06 §3; ADR 0026 §3–4 (T1 data, runs, pass rule); ADR 0027 (T1 text);
  ADR 0028 (E3 protocol, §11 base numbers, §12 per-window conditions)
- Config keys affected: `configs/training.yaml: t1` (new); `configs/pins/ami_dev_headsets.json`
  (after the run)

## Context

ADR 0026 §4 fixes T1's pass rule and ADR 0028 the E3 protocol that scores it, with base numbers
from run b5. PR-4 trains the first T1 model, **whisper-small on DisfluencySpeech train only**
(T1-r1), picks a checkpoint on dev data, exports it in the app's format and scores it on E3. All
of it runs on Colab (ADR 0026 §1); the laptop only builds the notebook, ingests the zip and
compares numbers.

## Decision

### 1. Runs are named, never repeated (owner, Q1)

The values in `configs/training.yaml: t1.r1` may change **only as a new named run** (r1b, r2,
r3, …), **never by re-running r1 after its test numbers are seen**. Every run is reported,
including one that fails the pass rule. The model pick stays on dev only (§5).

### 2. Training settings (owner Q1, PROVISIONAL)

Unsloth LoRA, following the official Unsloth Whisper notebook: rank **64**, alpha **64**, dropout
0, target modules **`q_proj`, `v_proj`**; AdamW 8-bit, learning rate **1e-4**, linear schedule,
**50** warm-up steps, weight decay 0.001; batch **8 × 2** gradient accumulation (16 clips per
step); **fp16** (a T4 has no bf16); **3 epochs**; seed **20261128**. Unsloth and unsloth_zoo
**2026.11.12** (the current release when built).

- **Data:** DisfluencySpeech train (4,500 rows, revision `b7da294`), text from the T1 builder on
  `transcript_annotated` (ADR 0027 §1); the builder check (ADR 0027 §6) runs first, as in E3. A
  row whose labels exceed Whisper's 448 decoder tokens is dropped and counted.
- **Model:** `openai/whisper-small` at the app's revision, every source file checked against
  `models/MANIFEST.json`, loaded from that local copy (not a mirror).
- **Procedure:** training runs in its own process, so the GPU is free afterwards. Log-mel
  features are computed when a batch is drawn (the whole set never sits in memory). One LoRA
  checkpoint per epoch goes to the owner's Drive, **outside** the results folder (not in the zip);
  an interrupted run resumes from the last checkpoint.

### 3. Export: the app's format

For each epoch's checkpoint, the LoRA weights are merged into the **original fp32 base weights**
by plain arithmetic, W' = W + (B·A)·alpha/r, for each adapted layer (`t1merge.py`, tested; no
PEFT or transformers version involved). The adapter must be plain LoRA with the run's rank and
alpha, and only `q_proj`/`v_proj` weights may change; otherwise the run stops. Every other tensor
and **every other file is the base's own pinned file** (config, generation config, tokenizer), so
the weight names, the decoder settings and the tokenizer are the app's.
The merged model is converted with **the app's converter** (`configs/models.yaml: converter`,
int8, the same `copy_files`) in the uv environment of ADR 0028 §6.

### 4. Decoding: the app's settings

Every candidate and the picked model are decoded with `e3.decoding` (ADR 0028 §1), **no prompt**,
by the E3 code itself (the built E3 script is a module of this run), so T1 is scored exactly like
base.

### 5. Pick on dev only (owner Q2)

- **Sets:** DisfluencySpeech validation (250 clips) and **AMI dev** (ES2005, IS1001, TS3005: the
  disfluency-layer pool minus the test sessions), segments with the deciding crosstalk filter.
- **Score:** the **mean of the two sets' lexicon filler F1**. Candidates within **0.005** of the
  best score tie; a tie goes to the **lower mean WER over the same two sets** (the E3 WER
  normaliser, fillers kept); identical WER as well → the earlier epoch.
- **LibriSpeech stays test-only**, and no test set is decoded before the pick is written.

### 6. AMI dev headsets (owner Q4)

48 files (3 sessions × 4 meetings × 4 headsets) from the official Edinburgh site, inside the D1
approval. **Pinned on first download:** each file's SHA-256 is written to
`pins/ami_dev_headsets.json` on Drive as it arrives, and the file goes to the Drive cache under
that hash; a resumed run uses those hashes as pins. After the run the pins are committed to
`configs/pins/ami_dev_headsets.json` and checked in every later run.

### 7. E3 on the picked model

The ADR 0028 protocol with condition **`t1`**: DisfluencySpeech test (reported), AMI test
(deciding, and crosstalk kept), PodcastFillers test (deciding), LibriSpeech test-clean (WER),
AMI repetitions kept. Per-unit counts (meeting, episode, clip, speaker; numbers only, no text)
are written for the paired comparison (§10).

### 8. Per-window conditions (ADR 0028 §12), report-only

Run in this Colab run, over the 20 PodcastFillers test episodes: **base + `initial_prompt` in
every window** (base model) and **T1 in every window** (T1, no prompt), on the same chunks.
Chunking as ADR 0028 §12, with these details fixed now, before any number:

- A speech region longer than 30 s is first cut into 30 s pieces; pieces and regions are joined
  in order into groups whose speech, from first start to last end, spans at most 30 s.
- Each group's chunk reaches out into the pauses on both sides, **up to the middle of each
  pause**, but never so far that the chunk exceeds 30 s; the slack is shared (half each side, the
  rest to the side that needs it). The first chunk starts at 0 s, the last ends at the episode's
  end.
- A part of a long pause that no neighbouring chunk can take within 30 s becomes its own chunk
  (cut every 30 s), so **no audio is dropped**.
- Word times are shifted by the chunk start; scoring is ADR 0028 §4 (time match, ±0.2 s).

### 9. Publish (owner Q3)

The picked model goes to the private repo **`Heemo-Beemo/presenceai-whisper-small-verbatim`**:
the CT2 int8 files under `ct2-int8/`, the LoRA adapter under `lora/`. The token is the Colab
Secret `HF_TOKEN` (a fine-grained write token for this repo only), used by name and never
printed. `run_info.json` records the **HF commit SHA** of the upload and the **SHA-256 of every
uploaded file**; PR-5's `download_models.py` pins that commit and those hashes. The owner revokes
the token at the end of P4. A load check on Colab CPU (faster-whisper, int8) decodes one clip.

### 10. Pass rule, scored on the laptop

`colab_t1.py compare` reads the ingested T1 metrics and b5's (ADR 0028 §11) and applies **ADR
0026 §4 unchanged**:

1. filler F1 ≥ base + 0.05 on AMI test **and** PodcastFillers test;
2. filler F1 above base + `initial_prompt` on both (AMI test: **0.815**, CI 0.790–0.841);
3. precision ≥ base − 0.02 on both;
4. AMI repetitions kept ≥ base;
5. LibriSpeech WER ≤ base + 1.0 point.

Point estimates decide, as written. Paired bootstrap 95 % intervals of each difference (T1 minus
base, T1 minus base + prompt; resampled by meeting / episode, ADR 0028 seed) are reported beside
them. The base per-unit counts are recomputed from b5's hypotheses on the laptop and must give
b5's totals exactly. This step scores text only and runs no model. If T1 does not beat
base + `initial_prompt` on AMI test, that is reported as a finding; **the line is not moved**.

## Consequences

- PR-4 ends with T1-r1's numbers, pass or fail. T1-r2 (+ AMI training meetings) is a new named
  run in PR-5, as are any changed settings (§1).
- PR-5: `download_models.py` pins the HF commit and file hashes from this run's `run_info.json`;
  the model card is drafted there.
- **This decision is wrong if** the adapter changes any weight other than `q_proj`/`v_proj` (the run
  stops),
  if a candidate is picked with any test data, or if the base counts recomputed on the laptop do
  not give b5's totals (then the comparison would not be like for like).
